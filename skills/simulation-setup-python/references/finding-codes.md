# Finding codes: the rest of the emitted set

`simulation-setup-python/SKILL.md` Step 9e.3 carries the codes an operator hits while AUTHORING
`plurai.config.yaml` / `simulate.py`. This page carries the remainder, so that the two together are
the WHOLE emitted set and neither has to grow to hold the other.

**How that "whole" is enforced.** Each verifier DECLARES the codes it can emit, as an enum at the
top of its own script — `Code` in `verify_config.py` and `verify_simulate.py`, `Category` in
`verify_smoke.py` — and every emission site takes its code from that enum rather than spelling a
literal. The plugin's tests then fail when a declared code has no row
in SKILL.md or here, when a row names a code no script declares, and when an emission site
hand-types one. Each registry is RESTATED rather than imported because Step 9e/9f copies each
script ALONE into the customer's `plurai_sim/`, where no sibling script is on the path.

Two families live here rather than in the step, for one reason each:

- **The checks that report they did NOT run.** `*_unknowable`, `*_check_skipped`,
  `*_unverifiable`, `*_unreadable`, `*_unparseable`. These say a gate was unavailable, not that
  the bench is wrong. The operator action is to supply the prerequisite (a dependency, a schema, a
  readable file) or to accept that the check is not covering this run — never to edit the harness.
- **The warnings about a DEGRADED declaration.** The descriptor written as prose rather than as
  the structured dict, a state-bearing return field the inline mock never sets. The upload
  succeeds and the run passes; what is lost is the backend's richer mock generation.

## Turn-smoke gates — the harness answered, and what it answered is wrong

`verify_smoke.py --turn` mints these as `plugin.smoke.<gate>` findings (exit 1; `trail_result_missing`, `trail_tool_untyped`
and `tool_history_dropped` are warnings that hold nothing, exit 0). They are `SmokeGate` members, not `Category` classifications, so they sit outside the code tables.

| Gate | What's wrong | Fix |
|---|---|---|
| `trail_result_missing` | The smoke turns reported tool-trail entries whose dispatch did not fail, and EVERY one carries no `result`. The first run's `run.json` names the same fault as `run_integrity.tool_trail_results_missing` | Set each entry's `result` to the value the tool returned, recorded at the tool wrapper when the framework's trace carries no outputs. A smoke whose turns called no tool prints `~ trail results: not exercised` |
| `trail_tool_undeclared` | `--turn` or `--pipeline`: a returned tool-trail row's `tool` is no declared name (`tools` key, render verb, `agent.native_tools` entry) but is the framework's wire name of EXACTLY ONE `tools` key (CrewAI's `sanitize_tool_name`: `create_draft` for `Create Draft`). The message names each pair. Every lookup by the key in the harness (a filter on `row['tool']`, delegation links) silently misses it | Record the declared key as the row's `tool` where the trail row is built (`framework-patterns.md`, "The trail row's tool name"). Overrulable, never hard |
| `trail_tool_untyped` | `--turn` or `--pipeline`, a WARNING (exit 0): the config declares `render_actions` (a closed surface) and a returned tool-trail row the framework ran (`status: ok`) names no declared name, is the wire name of no `tools` key, and differs from every declared name in more than case and separators. The runtime adds a function on the agent's behalf (a memory tool, a delegation or transfer call) that the scan never typed, so the backend charges every call of it as invented | Type it on the map first: a live tool row in `artifacts/agent_topology.json` with `writes`, `effects` and `runs` (scan Step 2a), map re-rendered (scan Step 2b); then `tools.<name>: {mode: real, observation_lane: tool_trail}`, its descriptor citing the framework source that adds it. If no framework code adds it, the harness records the row `not_dispatchable`, never `ok` |
| `channel_refused` | `--turn` planted a probe through every `agent.io.channels` entry (a file item, a context value, a host message, a between-turn write) and the harness raised on that turn. Every scenario that plants into the channel would die there | Make `invoke_agent` read each channel's `field` the way the agent's request does (and `apply_user_action` take a channel write, `surface` = the channel name), or drop the channel |
| `document_undelivered` | A `.document_fields` document was handed over as a `file` part on the opener (a text one carrying its own reference code) and the harness never read the part (the SDK's `unread_parts` read record). On an SDK with no read record, the agent could not quote the text document's code when asked. An agent that stores the upload (records, a dataset) instead of quoting it passes once the harness read the part | Read every turn with `turn_documents(content)` and hand the agent each document the way the product does (its upload channel, or a planted file named by path) |
| `tool_history_dropped` | A WARNING (exit 0), two paths (`observed.path`). `live`: turn 1 asked the agent to look something up with a read-only tool, and on turn 2, told not to call a tool, it gave back none of the values that tool returned (asked for two or three entries, the agent picks which, so an id its policy hides is never required), so the harness keeps only user and final assistant messages between turns. A heuristic on free text: a paraphrased value trips it. A re-call of the tool on turn 2, a reply 2 that gives back only values the turn-1 reply already said or only one-word values (letters alone, which prose holds by chance), or a turn 2 that lost the name too is `~ not measured`. `resume`: Init refused the canned seed holding a tool call and its result and accepted the same conversation without them, so regressions with tool calls cannot replay | `live`: keep every message a turn produces in the thread history (bridge: the shape production stores, or the bridge runtime adapter's `turnMessages`; LangGraph: a checkpointer). `resume`: pass each seed message whole, `tool_calls` and `tool_call_id` included (`resumed-seed-state.md`); a harness whose memory cannot hold tool messages keeps the warning |
| `canned_resume_refused` | Init refused a canned `type`-keyed resume seed — on a harness that defines `seed_state` and does not declare `harness.resume.mode: unsupported`. The usual cause is a speaker read from `role` (the seed carries `type`), caught by the restored-count tripwire | Read each message's `type` and restore every one (`resumed-seed-state.md`). Only where the conversation lives in a session the harness cannot write, declare `harness.resume.mode: unsupported`; a harness that records its session and resumes it is not one. A harness whose turns report a recorded CLI session (`cli_session`) is not offered the canned seed |

## World read-back gates — the seed was accepted, then read back

`verify_smoke.py --seed-world <file|dir>` (the manifest's `seed_readback` check) and the Init smoke mint these, advisory
and holding until one harness-lane repair round, or an overrule with the reason. "Seed accepted" and "read back as
seeded" are separate facts; acceptance alone is never a round-trip.

| Gate | What's wrong | Fix |
|---|---|---|
| `seed_readback_gap` | `seed_state` accepted the world, but the Init's own post-seed read does not return it as seeded: rows missing, fields the read never returns, fields changed, or the read failed. No read path at all is NO VERDICT (exit 2), never OK | not in the read → make `world_snapshot` return it; changed → make `seed_state` apply it; read failed → fix that exception |
| `confirmed_store_seed_readback_gap` | The same gap on a bench whose `world_state.confirmation` holds a `disposable_copy`: the harness seeds that live store itself. Hard | Make `world_snapshot` return the seeded rows, or `seed_state` apply them |
| `world_read_raised` | The Init smoke's post-seed read carries a crash marker: every run would compare its seed against no world | Fix what the read raised (`world_snapshot`) |
| `reset_leftover` | An empty Init after the probe world still reads a probe row the empty Init before it did not: `reset()` does not clear the store `seed_state` writes | Make `reset()` clear that store |

An advisory turn-smoke note, which never changes the exit: `⚠ trail lane unwritten (TRAIL_LANE_UNWRITTEN)` prints when
the turns' chain shows a call to a tool declared `observation_lane: tool_trail` and no turn wrote `agent_state['tool_trail']`.
Record each call of those tools on `tool_trail`, or declare the lane their calls really ride. Likewise
`⚠ trail tool unresolved (TRAIL_TOOL_UNRESOLVED)` prints when a trail row's `tool` is no declared name, is the wire
name of no `tools` key or of several, and is not `trail_tool_untyped`: record the declared key on the row, or declare the
tool under the name the trail carries.

## Read / parse failures — the verifier could not see a file

Both static verifiers discover the same optional split helpers (`_storage.py`, `_mocks.py`,
Step 8.4), so `helper_*` comes from either one; the finding names the file.

| Code | Verifier | What's wrong | Fix |
|---|---|---|---|
| `simulate_unreadable` | verify_config | **Warn-only.** `simulate.py` could not be READ at all (permissions, a broken symlink). Every AST-dependent check against it is skipped, so the exit code is about the config alone | Make the file readable, then re-run. A clean exit while this is present does not mean the harness was checked |
| `simulate_unparseable` | verify_config | **Warn-only** — the config's own checks still run, so the exit code is about the config alone. `simulate.py` does not parse; the finding carries the line. `verify_simulate` reports the same file as a **fail**, under `syntax_error` | Fix the syntax error first — every cross-document finding in this run was measured on a file the verifier could not read |
| `helper_unreadable` | verify_config, verify_simulate | **Warn-only.** A discovered split helper could not be read. The checks that need its AST are skipped and nothing else says so | Make it readable, or delete it if it is a stale copy the discovery walk is picking up |
| `helper_unparseable` | verify_config, verify_simulate | **Warn-only.** A discovered split helper does not parse; the finding carries the file and line | Fix the syntax error. Until then the storage / mock-dispatch checks against that helper are not running |
| `helper_naming_convention_drift` | verify_config | **Warn-only.** A file next to `simulate.py` looks like a split helper under a near-miss name (`mocks.py`, `storage_helpers.py`), and discovery auto-finds only the canonical `_storage.py` / `_mocks.py`. So the helper exists, is imported by the harness, and is checked by nothing | Rename it to the canonical name (or symlink), then re-run — Step 8.4 |
| `syntax_error` | verify_simulate, verify_smoke | `simulate.py` (or a helper) does not parse. In `verify_smoke` it is the CATEGORY the child's crash classifies to, which is why the same word appears in two registries | Run `verify_simulate.py` + `verify_config.py` first — they carry the file and line; the smoke test only tells you the child died on one |

| `delivery_surface_undetermined` | verify_config | **Warn-only.** Whether `world_snapshot()` returns a delivery surface's rows cannot be read from the harness source: it computes `_entity_type`, or its body lives outside the harness files | Nothing to change at scan time. If the rows are missing, the run reports the surface as not captured — simulation-setup Step 8 |
| `inline_action_without_hook` | verify_config | A surface declares actions on rows inside a list field, and `simulate.py` exports no `apply_user_action`. Such rows are only ever written by the harness, so every act of the simulated user on them is unexecutable | Add `def apply_user_action(act: dict) -> None` to `simulate.py`, writing the edit the way the product does — simulation-setup Step 8 |

## A bridge bench's map, routes and toolchain

A non-Python agent runs under `simulate.py` driving a bridge child (`simulation-setup-bridge`). Two scripts check it, both
run from the plugin: `verify_bridge.py` (the map statically, then a model-free route probe) and `bridge_preflight.py`
(what this machine and this agent need before anything is generated). The map's codes are declared by `bridge_map.py`
(the map validator) and reported by `verify_bridge.py`.

| Code | Verifier | What's wrong | Fix |
|---|---|---|---|
| `bridge_map_invalid` | bridge_map | `bridge/bridge.map.json` breaks `plurai.bridge.map/1`, names an entry, `replace` or `impl` file that is not under `bridge/`, maps a refused package (`raw_sql_driver`, `builder_chain`, `command_dispatch`), or breaks a rule the schema cannot say (a `*kw` param not last, a call that is also a `local`, a route whose default params clash, a route path param that names more than one segment, a route `params` source `path.<x>` with no `:<x>` segment, a host pattern with no literal label (`*`, `*.*`), which matches every host, a `subpaths` entry that does not start with `<package>/`, a `subpaths` entry that is itself a refused package, a `modules` key with a `..` segment, an `evidence` file that is absolute or has a `..` segment and so escapes the agent root). The finding names the JSON pointer | Fix the entry it points at; for a refused package, map the seam the message names instead; for a too-broad host pattern, name the host or its domain |
| `bridge_evidence_invalid` | bridge_map | An `evidence` cites a file that is not under the agent root, a line past its end, or (for a `packages` entry) a file that never imports the specifier | Cite the agent `file:line` that shows the call or the import |
| `bridge_tool_not_declared` | bridge_map | A map entry routes to a tool that is not a `mode: mock` tool of `plurai.config.yaml` | Declare the tool, or route the call to the tool that is declared |
| `bridge_tool_not_mocked` | bridge_map | A map entry routes to a tool that is not in `simulate.py`'s dispatch table (`_MOCKED`), so the host refuses to start | Add the tool's `@plurai.mock` and its `mock_wrap` row |
| `bridge_tool_unreachable` | bridge_map | **Warn-only.** A `mode: mock` config tool no map entry routes to: the agent can never reach its mock through the bridge | Map the call that reaches it, or set it `mode: real` if the agent never makes it |
| `bridge_passthrough_is_production` | bridge_map | A `passthrough_hosts` or `sink_hosts` host matches a host of `egress.production_hosts`, so the agent would reach production | Route that host to its mock tool with an `http` entry |

| `bridge_probe_failed` | verify_bridge | The route probe did not complete: `simulate.py` has no `_bridge_host()`, the host refused to start, or the child died. | `bridge_mock_param_required` | verify_bridge | **Warn-only.** A function `_MOCKED` dispatches has a parameter with no default (a `**kwargs` cannot supply it). The bridge sends only the keys the call carried (`undefined` is dropped, a spread brings only the object's own keys), so a call that leaves the key out is a HarnessFault on that turn, not a tool failure; the route probe sends `null` for a named parameter, so it misses this case | Give every `@plurai.mock` parameter a default (`=None`) |

`scripts/stage-inputs.sh` stages a bridge bench's required files: the map's `entry.path`, every `replace` and `impl`, and
the runtime files the bridge constants list. It stages the rest first, then reports each required path that is absent,
gitignored or unknowable as `MISSING` or `ERROR` and exits **4**. Write or un-ignore the path it names, then re-run.
